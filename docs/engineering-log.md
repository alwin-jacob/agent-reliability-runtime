# Engineering log

## 2026-08-25 — Stage 1 semantic-integrity correction

A later source audit, distinct from the earlier implementation-agent review recorded below, found that Stage 1 order and policy evidence was not bound to one typed task context. Workers could select schema-valid but unrelated order/policy arguments, the finalizer checked only order ID and policy-window length, and the task had no fixed decision date. As a result, order/policy market, category, and purchase channel mismatches; unsupported item condition; arbitrary eligibility/code; and wall-clock-ambiguous time-window conclusions were possible.

The same audit found cross-record artifact bypasses. A writer could modify and reseal top-level versus final-state task/decision values, worker outputs versus accepted tool results, tool-result identities, persisted plans, durable IDs, attempt numbering, or timestamps. The existing hashes would then recompute successfully because hashes are unkeyed modification detectors, not digital signatures and not proof of writer authenticity. Cancellation cleanup also allowed a cancelled-artifact persistence exception to replace the original `CancelledError`, while phase state was published before its transition event was recorded.

The correction bumps package and current task/config/artifact/fixture schemas to `0.2.0`, retaining the `0.1.0` artifact schema as historical evidence. `TaskSpec` now requires exact valid-calendar `as_of_date`, `item_condition`, `market`, `item_category`, and closed `purchase_channel`. Both workers remain concurrent, but their requested tool and exact arguments are checked against that task. `semantics.py` now supplies one pure contract for the exact plan and task-bound calls and for delivered order evidence, context and condition equality, deterministic calendar-day derivation, inclusive-window eligibility, canonical codes, policy fees/window, and exactly both worker IDs. Live orchestration maps those errors to nonretryable typed model-output failures; artifact validation maps the same errors to artifact failures.

Artifact validation now compares top-level/final-state records, reconciles exactly one successful result and logical tool call per required worker to the terminal successful tool result, checks tool-result identity, validates the exact persisted plan, rejects duplicate durable IDs and noncontiguous attempts, parses all durable timestamps as UTC `Z`, checks run/model/tool time ordering, and reapplies the pure success semantics. Every adversarial artifact test recomputes configuration, semantic, and content hashes before rejection. Cancellation persistence failures are retained as sanitized notes while the original cancellation is re-raised, and phase publication occurs only after its transition event is durably appended to the in-memory stream.

Remaining limitations are explicit: exact `ModelRequest` payload persistence/replay is absent even though attempts and provider responses persist; request persistence or request digests must be decided before trajectory replay or real-provider evaluation. `LoadedInputs` contains a stateful fixture provider intended for one execution, so per-run provider construction is required before repeated sampling. Evidence is in memory until the final atomic write; checkpointing, process resume, human interrupts, real providers, external observability, benchmarks, and evaluation-repository integration remain unimplemented. The earlier implementation-agent review did not identify these later-audit issues and is not represented as having done so.

## 2026-08-23 — Stage 0 and deterministic Stage 1 decisions

Low-level LangGraph `StateGraph` was selected because the milestone needs inspectable node/edge semantics, dynamic `Send` fan-out, one generic worker node, explicit reducer state, and an injected runtime context. A prebuilt agent abstraction would hide the exact graph and tool-policy boundaries this repository is intended to test.

Checkpointing and human-in-the-loop behavior were excluded from Stage 1 because durable resume and human interrupts change state compatibility, persistence, security, and operational semantics. Graph state is kept serialization-ready now, but adding empty checkpointer or `HumanDecision` code would imply unsupported behavior.

Runtime retries are distinct from evaluation retries. A single agent run internally controls each model/tool attempt, timeout, classification, and backoff. A future `llm-eval-reliability` adapter should therefore default the evaluation engine's outer candidate attempts to one; wrapping a whole internally retried run in another retry loop would distort accounting and failure attribution.

Full artifacts are not expected to be byte-identical. Run/event/attempt/tool identifiers, UTC timestamps, measured durations, source commit/dirty state, and real concurrent observation order are intentionally truthful and volatile. Semantic reproducibility is tested by hashing stable inputs and normalized outcomes, executing twice, comparing the semantic fingerprints, and comparing a stable artifact projection after removing only documented volatile fields.

The concurrency test does not rely on elapsed time. Both workers enter an injected active-section barrier and neither is released until both are present; a sequential worker implementation cannot satisfy it. A separate one-slot test checks the observed maximum never exceeds the configuration.

Failure and negative evidence are first-class. Tests demonstrate permanent failures do not retry, transient failures do, each attempt has an independent timeout, malformed/schema-invalid model output does not retry, tool policies and schemas fail closed, cancellation propagates to active work, accounting reconciles, invalid lifecycle evidence is rejected, and atomic replacement failure leaves no partial final.

The earlier implementation-agent review found eight actionable but different integrity/contract issues: validation ordering for tool references, required lifecycle-event validation, synthetic token labeling, ignored jitter configuration, contradictory attempt evidence, unconstrained fixture digests, incomplete stable-projection comparison, and incomplete unexpected CLI normalization. Those were fixed and regression-tested in the earlier milestone. That review did not identify the later semantic-integrity defects corrected on 2026-08-25.

Features deliberately not implemented include checkpoint/resume, human interrupts/approval, MCP, sandbox/Docker, network/filesystem execution tools, RAG, Langfuse or configured LangSmith observability, FastAPI, real providers/fallback, benchmarks and submitted percentages, repeated sampling, annotations/raters/calibration, derived regression thresholds, significance claims, and changes to `llm-eval-reliability`.

Limitations at that milestone included in-memory evidence until the atomic final write, one-process execution, fixture-only behavior, no remote CI evidence, and unresolved public-release licensing. The 2026-08-25 corrective verification supersedes its local-version and test-count snapshot.
